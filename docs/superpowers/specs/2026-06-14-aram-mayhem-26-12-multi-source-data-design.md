# 26.12 海克斯大乱斗多源数据设计

## 1. 目标

为 LOL Companion 建立独立的 **海克斯大乱斗（ARAM: Mayhem）26.12 数据域**，每天自动同步官方元数据、国内外统计站数据和玩家社区候选组合，生成可追溯、可回滚的推荐快照。

本轮只处理海克斯大乱斗，不处理斗魂竞技场。匹配与排位仍沿用韩服钻石及以上数据口径；海克斯大乱斗使用全分段大样本。

产品提供两种推荐模式：

- **强度优先**：默认模式，侧重胜率、样本稳定性、英雄适配和已选海克斯协同。
- **黑科技**：侧重低选取率、高收益且有实战样本支撑的组合，有效样本必须不少于 500 场。

## 2. 版本事实与迁移边界

国服于 2026 年 6 月 11 日上线 26.12。该版本对海克斯大乱斗进行了结构性更新，包括移除羁绊系统、将部分效果迁移为新强化并加入大量新强化。

参考来源：

- 国服 26.12 更新公告：https://lol.qq.com/gicp/news/410/37088140.html
- Riot 26.12 版本说明：https://www.leagueoflegends.com/en-us/news/game-updates/league-of-legends-patch-26-12-notes/
- Riot 海克斯大乱斗开发者说明：https://www.leagueoflegends.com/en-us/news/dev/dev-augmentmaxxing-aram-mayhem/

现有 `arenaAugments`、`metabotArenaAugments`、`ArenaRecommendation` 等命名主要对应斗魂竞技场或混合原型数据，不能直接视为海克斯大乱斗 26.12 数据。实施时必须建立新的 `aram-mayhem` 命名空间，旧数据只作为迁移参考，不参与新版本正式评分。

## 3. 数据源分层

### 3.1 官方与静态元数据

用途：确定版本、强化 ID、名称、描述、稀有度、图标、上线与移除状态。

- Riot 国服和全球版本公告。
- CommunityDragon 当前版本游戏资源。
- Data Dragon 中可用的英雄、装备及本地化资源。
- 本地 LCU 与 Live Client Data，用于识别当前模式、英雄、已选强化、当前三选一候选、装备和游戏时间。

官方层是身份与规则事实来源，不承担组合胜率推断。

### 3.2 海外统计站

候选来源包括 OP.GG、MetaBot.GG、LeagueOfGraphs、METAsrc，以及后续确认具备稳定接口或允许自动访问的站点。

用途：

- 强化选取率、胜率或排名指标。
- 英雄与强化适配数据。
- 强化组合、装备路线和样本量。
- 不同站点间的交叉验证。

每个站点使用独立适配器。页面结构变化、访问限制或统计口径不明时，该来源应降级或停用，不能阻断其他来源更新。

### 3.3 国内统计站与玩家社区

候选来源包括掌上英雄联盟、101 战绩、NGA、贴吧、Bilibili 攻略及其他活跃社区。只有可合法访问、可稳定解析并能明确标注来源的数据才进入自动采集。

国内社区主要负责发现：

- 新版本热门组合。
- 低选取率的黑科技强化链。
- 特定英雄与装备联动思路。
- 玩家对新强化名称、机制和实际触发条件的补充描述。

社区内容只能进入“候选池”，不能直接成为胜率证据。正式黑科技推荐必须由同版本结构化统计数据验证，样本量不少于 500 场。

### 3.4 自有聚合

长期目标是在符合 Riot 政策和接口能力的前提下，对可获得的对局记录进行自有聚合，形成：

`英雄 + 已选强化 + 候选强化 + 装备路径 + 对局结果`

自有聚合是未来组合收益和置信区间的最高优先级数据，但不作为 26.12 首次交付的阻塞条件。

## 4. 统一数据模型

所有适配器输出统一的原始记录：

```ts
type MayhemSourceRecord = {
  sourceId: string
  sourceUrl: string
  collectedAt: string
  patch: string
  queue: 'aram-mayhem'
  population: 'all-ranks'
  locale: string
  championId: number | null
  selectedAugmentIds: number[]
  candidateAugmentId: number
  itemIds: number[]
  games: number | null
  wins: number | null
  winRate: number | null
  pickRate: number | null
  sourceConfidence: number
  evidenceType: 'official' | 'aggregate' | 'community-candidate'
}
```

聚合后的应用快照：

```ts
type MayhemRecommendationSnapshot = {
  schemaVersion: number
  patch: string
  generatedAt: string
  expiresAt: string
  completeness: number
  sources: SourceHealth[]
  augments: MayhemAugment[]
  recommendations: {
    strength: MayhemRecommendation[]
    offMeta: MayhemRecommendation[]
  }
}
```

每条推荐必须保留：

- 来源列表和原始链接。
- 当前版本和采集时间。
- 总样本量与参与聚合的站点数量。
- 评分分解和可信度。
- 已选强化与候选强化的协同说明。
- 推荐装备图标链。

## 5. 清洗与聚合规则

### 5.1 模式与版本隔离

- 只接收 `aram-mayhem` 数据，拒绝普通大乱斗和斗魂竞技场数据混入。
- 26.11 及更早统计不能参与 26.12 主推荐。
- 官方元数据确认已移除的强化不得出现在候选推荐中。
- 新版本发布后，旧快照可作为离线兜底展示，但必须标记过期，不能显示为当前版本结论。

### 5.2 身份对齐

- 优先使用官方强化 ID、英雄 ID 和装备 ID。
- 站点只提供名称时，经过中英文别名表和标准化规则映射。
- 无法唯一映射的记录进入隔离区，不参与评分。
- 同一记录按来源、版本、英雄、已选强化集合、候选强化和装备链去重。

### 5.3 多源加权

不同站点不能直接平均。单条指标的权重由以下因素共同决定：

- 来源可靠度。
- 样本量。
- 数据新鲜度。
- 版本与模式匹配程度。
- 是否提供明确统计口径。
- 与其他独立来源的一致程度。

来源冲突较大时降低置信度并标记“观察中”，不伪造高精度概率。

## 6. 推荐评分

### 6.1 强度模式

最终分数为 0 到 100，权重如下：

- 胜率：40%。
- 样本稳定性与跨来源一致性：25%。
- 当前英雄适配：20%。
- 与已选强化的协同：15%。

海克斯大乱斗是 5v5 胜负制，不使用斗魂竞技场的前四率或平均名次。样本稳定性由样本规模、数据新鲜度和独立来源一致程度计算；缺少某项有效指标时，权重按已获得指标重新归一化，并在评分分解中注明缺失项。

### 6.2 黑科技模式

- 组合收益：35%。
- 稀有度：25%。
- 当前英雄适配：20%。
- 跨来源稳定性：20%。

准入条件：

- 同版本有效样本不少于 500 场。
- 至少一个结构化统计来源提供结果指标。
- 不与官方元数据冲突。
- 社区帖子只能作为候选发现来源。

“稀有度”鼓励低选取率，但不能奖励明显低收益组合。组合收益为负或置信区间过宽时不得进入黑科技正式榜。

### 6.3 实时三选一

输入：

- 当前英雄。
- 已选强化集合。
- 当前出现的三个候选强化。
- 当前装备、游戏时间和可获得的实时状态。
- 当前 26.12 聚合快照。

输出：

- 三个候选的排序和评分。
- 每个候选一条简短、可验证的原因。
- 与已选强化的直接协同或冲突。
- 对应装备图标链。
- 样本量、更新时间和可信度。

推荐器不得给当前未出现的强化，也不得把全局榜单分数直接当作本局三选一结论。

## 7. 每日更新管线

新增独立 GitHub Actions 工作流，每天执行一次，也支持手动触发：

1. 检测国服当前版本。
2. 拉取 Riot 与 CommunityDragon 元数据。
3. 运行各统计站适配器。
4. 运行社区候选发现适配器。
5. 标准化、版本校验、去重和冲突检测。
6. 生成强度与黑科技推荐快照。
7. 执行数据质量测试。
8. 成功时提交或发布新快照；失败时保留上一份有效快照并上传诊断报告。

单站失败只影响该站点健康状态。只有以下情况阻止新快照发布：

- 当前版本无法确定。
- 官方强化身份表为空。
- 快照包含跨模式或跨版本记录。
- 新强化无法完成唯一 ID 映射。
- 完整度低于约定发布阈值。

初始发布阈值为：官方强化身份覆盖率 100%，至少一个结构化统计来源成功，所有正式黑科技记录满足 500 场门槛。

## 8. 应用数据流

桌面应用启动后：

1. 从内置快照立即渲染，不等待网络。
2. 检查本地快照版本与 LCU 检测到的游戏版本。
3. 后台下载更新后的签名或校验和快照。
4. 校验 schema、版本、文件哈希和最小完整度。
5. 原子替换本地缓存，并触发推荐视图重算。
6. 网络失败时继续使用最近有效快照，显示实际版本和更新时间。

应用不在对局中临时抓取多个第三方网页，避免延迟、站点限流和结果不一致。

## 9. 产品展示

海克斯实时页新增轻量模式切换：

- `强度`
- `黑科技`

三选一卡片保留游戏图标风格，不增加大段教学文字。每项只显示：

- 强化图标与名称。
- 推荐分数。
- 一句协同原因。
- 样本量与可信度。
- 联动装备图标。

数据来源和更新时间集中显示一次，不在每张卡片重复。数据过期、来源不足或样本不足时，明确显示“数据观察中”，不使用 Demo 数值伪装真实统计。

## 10. 错误处理与合规

- 适配器必须限速、缓存并使用明确的 User-Agent。
- 优先使用官方 API、MCP、公开结构化数据或站点允许的访问方式。
- 遇到登录墙、验证码、Cloudflare 挑战或明确禁止自动抓取时停止自动采集，不绕过保护。
- 不收集玩家密码、Cookie、登录令牌或私人账号信息。
- 第三方来源必须保留出处，支持单独禁用和删除。
- 来源页面结构变化时，解析器应失败关闭，不能悄悄输出空数据或错误字段。

## 11. 测试与验收

### 11.1 数据测试

- 版本隔离：26.11 记录不能进入 26.12 快照。
- 模式隔离：斗魂竞技场记录不能进入海克斯大乱斗快照。
- 移除校验：26.12 已移除内容不得被推荐。
- 新增校验：官方新增强化必须完成 ID、名称和图标映射。
- 去重校验：重复来源记录不会重复计入样本。
- 黑科技门槛：499 场不可发布，500 场可进入后续评分。
- 冲突校验：来源差异过大时降低可信度。
- 失败回退：单站失败仍可使用其他来源；核心校验失败则保留上一快照。

### 11.2 推荐测试

- 三选一只排序当前出现的三个强化。
- 已选强化变化后，协同评分与原因随之变化。
- 强度与黑科技模式能产生不同但可解释的排序。
- 装备链随强化组合变化，且只使用图标展示。
- 缺少结果指标时正确重算权重，不引入斗魂竞技场排名指标。

### 11.3 首次发布验收

- 应用明确显示当前数据版本为 26.12。
- 26.12 新强化完整出现，旧羁绊不再作为可选系统展示。
- 海克斯大乱斗使用全分段数据。
- 匹配与排位仍使用韩服钻石以上数据。
- 强度与黑科技可切换。
- 正式黑科技推荐每项均有不少于 500 场有效样本。
- 每项推荐可追溯到来源、版本、样本量和更新时间。
- 每日工作流可自动更新，并在失败时保留最近有效快照。

## 12. 非目标

- 本轮不重做玩家情报和排位推荐界面。
- 本轮不处理斗魂竞技场数据。
- 本轮不承诺从无法合法或稳定访问的站点自动抓取。
- 本轮不将社区热帖点赞数当作胜率或强度证据。
- 本轮不实现游戏画面注入，继续使用桌面悬浮窗和本地客户端接口。

## 13. 实现落地状态（2026/06/14）

本设计已在分支 `claude/mayhem-26-12-data` 按实施计划 Task 1–10 完成，要点与现状如下：

- 命名空间隔离：新数据域位于 `src/features/mayhem/` 与 `data/mayhem/`，与 `arenaAugments` / `ArenaRecommendation` 完全分离，旧数据未被改名冒充本版本数据。
- 官方层：`scripts/mayhem/import-official.mjs` 从 CommunityDragon `cherry-augments.json` 取 170 个 `ARAM_` 前缀强化；`officialCoverage = 1`。
- 统计层：METAsrc / OP.GG 各自独立降级。当前 26.12 实测两站均不可用（METAsrc HTTP 403；OP.GG 客户端渲染、无可用记录），快照如实记录 `status: 'unavailable'` 与原因，管线不中断。
- 因无在线聚合源，`strength` 与 `offMeta` 当前为空（诚实留空，未编造），UI 走 `本地规则兜底 · 非版本统计` 与 `样本 —` / `置信 —` 占位；组合概率从不展示。
- 黑科技门槛 `OFF_META_MIN_GAMES = 500` 已在聚合与 `validate-snapshot.mjs` 双重把守。
- 快照权威实现为 `src/features/mayhem/snapshot.ts`，`scripts/mayhem/aggregate.mjs` 为 JS 镜像，由 `snapshot.test.ts` 的 parity 测试守护一致；`queue` 字段固定为 `'aram-mayhem'`。
- 每日管线：`.github/workflows/mayhem-data-refresh.yml`（cron `20 19 * * *`）跑 `data:mayhem:refresh` + `data:mayhem:check`。检查区分硬失败（版本/口径/`queue`/`officialCoverage`/off-meta 样本门槛，退出非 0）与软告警（聚合站点离线，退出 0），即单站离线不阻断核心校验。

### 13.1 已知限制：Live Client Data 不暴露强化

Live Client Data API（`/liveclientdata/allgamedata`）当前不暴露稳定的海克斯大乱斗「已选强化 / 三选一候选」字段。因此 `src-tauri` 的 `LiveClientSnapshotPayload` 对应字段返回空数组，前端 `isLiveDataAuthoritative` 为 false 时显示「等待同步」，绝不臆造已选或候选强化。对局内不抓取多页网络数据，仅读取预生成并经校验的本地快照。一旦官方暴露稳定字段，可在不改数据契约的前提下接入。
